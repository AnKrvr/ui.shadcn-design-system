# Дизайн-система shadcn/ui для создания сайтов

Дата: 2026-10-18
Репозиторий: https://github.com/AnKrvr/ui.shadcn-design-system
Статус: спецификация для согласования; реализация ещё не выполнена.

## Цель

Создать готовую основу, из которой Анастасия сможет собирать разные сайты с помощью ИИ.
Репозиторий должен содержать настоящий исходный код компонентов shadcn/ui,
единые стили, интерактивные примеры и понятные инструкции.
Новый сайт создаётся копированием или клонированием этой основы в отдельный проект.

Это шаблон фронтенд-проекта с дизайн-системой внутри.
Отдельный публикуемый npm-пакет и монорепозиторий на первом этапе не нужны.

## Подтверждённые требования и исходное состояние

- Источник компонентов: https://ui.shadcn.com/.
- Пользователь хочет получить все компоненты и использовать систему для сборки сайтов.
- Целевой GitHub-репозиторий пуст, доступ на чтение и запись подтверждён.
- Основной сценарий — дальнейшая работа с ИИ над интерфейсами в новых проектах.

## Выбранные настройки по умолчанию

- React, TypeScript, Vite, Tailwind CSS.
- Одна согласованная официальная конфигурация shadcn/ui на Radix, без смешивания баз.
- Исходное нейтральное оформление shadcn/ui, без придуманного брендинга.
- Светлая и тёмная темы на семантических CSS-переменных.
- npm и зафиксированный lockfile для воспроизводимой установки.
- Storybook как отдельный каталог компонентов, состояний и примеров.
- Стабильные совместимые версии зависимостей выбираются и фиксируются при реализации.

## Границы каталога

Включить все актуальные позиции раздела Components официальной документации
shadcn/ui на момент реализации. До установки сохранить проверяемый перечень
компонентов и соответствие исходным файлам и примерам.

Компоненты с установкой через официальный CLI добавить через CLI с настоящими
зависимостями. Использовать поддерживаемую команду добавления всех доступных
компонентов и сверить результат с сохранённым перечнем.

Позиции, представляющие композиции или рецепты, например Data Table,
Date Picker и Typography, реализовать по официальным примерам из уже добавленных
примитивов. Их нельзя считать отсутствующими только потому, что у них нет
самостоятельного установочного файла.

Для каждого элемента каталога должны быть:
- рабочий исходный код или документированная композиция;
- запускаемый пример в Storybook;
- краткое описание назначения и пример импорта;
- подходящие варианты и состояния.

Отдельные разделы Blocks, Charts с полным набором демонстрационных графиков,
AI Elements, внешние registries и полный сайт документации shadcn/ui
не включаются в первую поставку. Компонент Chart из раздела Components входит:
для него нужен рабочий пример графика, а не вся отдельная галерея Charts.

Нельзя подменять официальные реализации упрощёнными заглушками.
Если официальный элемент требует недоступного сервиса, это должно быть явно
отражено в перечне; локальный пример использует демонстрационные данные.

## Структура проекта

- src/components/ui/ — исходные компоненты shadcn/ui.
- src/components/patterns/ — составные элементы и официальные рецепты.
- src/components/examples/ — небольшие примеры использования.
- src/hooks/ — общие хуки.
- src/lib/ — утилиты, включая согласованную обработку классов.
- src/styles/ — семантические токены и глобальные стили.
- src/stories/ — Storybook: основы, компоненты, паттерны, пример страницы.
- src/App.tsx — стартовая демонстрационная страница.
- .storybook/ — настройки каталога и тем.
- docs/ — инструкции, перечень компонентов и решения по устройству системы.
- components.json — конфигурация официального shadcn CLI.
- AGENTS.md — правила для ИИ при создании сайтов.
- README.md — запуск, структура и начало нового сайта.

## Основы оформления

Цвета: фон, поверхность, основной текст, второстепенный текст, границы,
основное действие, вторичное действие, акцент, опасное действие,
кольцо фокуса, цвета графиков и боковой панели.

Размеры: использовать общую шкалу отступов Tailwind, согласованную типографику,
скругления и тени. Не вводить параллельный набор значений без необходимости.

Шрифты: системный стек по умолчанию, без обязательного подключения внешнего сервиса.

Переключатель темы работает и в демонстрационном приложении, и в Storybook.
В приложении выбор сохраняется локально; при первом открытии учитывается
системная тема. В Storybook тема выбирается через панель каталога.

## Каталог Storybook

Разделы:
1. Начало работы: как запустить систему и использовать её в новом сайте.
2. Основы: палитра, типографика, отступы, радиусы, тени.
3. Компоненты: весь сохранённый перечень из раздела Components.
4. Паттерны: формы, таблица с поиском и сортировкой, выбор даты.
5. Пример страницы: адаптивная демонстрация совместной работы компонентов.

Показывать только поддерживаемые состояния: default, hover через взаимодействие,
focus, disabled, loading, error, selected и open там, где они применимы.
Не придумывать пропсы или состояния, которых нет у компонента.

Для интерактивных элементов сохранять настоящие обработчики:
диалоги открываются и закрываются, формы проверяют ввод, таблицы сортируются,
уведомления появляются, контролы меняют значения.
Демонстрационные данные локальные и не зависят от бэкенда.

## Правила для ИИ

AGENTS.md должен предписывать:
- сначала искать подходящий существующий компонент;
- использовать компоненты через согласованные алиасы импортов;
- применять семантические токены и общую шкалу отступов;
- собирать сложные элементы композиционно;
- добавлять новый общий компонент только при отсутствии подходящего;
- сохранять семантику, подписи, фокус и управление клавиатурой;
- учитывать мобильные экраны и обе темы;
- после изменений запускать соответствующие проверки;
- не удалять и не переписывать каталог при работе над страницами сайта.

Для начала нового сайта README объясняет:
1. скопировать основу в новый репозиторий;
2. установить зависимости;
3. запустить приложение и при необходимости Storybook;
4. заменить демонстрационную страницу своими экранами;
5. использовать компоненты, токены и правила из этого проекта.

## Обработка ошибок и доступность

Формы содержат подписи и сообщения об ошибках, связанные с полями.
Диалоги и меню сохраняют стандартное управление фокусом и клавиатурой.
Пустые состояния, загрузка и ошибки показаны на применимых примерах.
Данные примеров не маскируются под реальные пользовательские операции.

Не отключать проверки TypeScript и не подавлять ошибки ради успешной сборки.
Сохранять лицензии и уведомления об авторстве исходных компонентов.

## Проверка готовности

- Установка зависимостей проходит с зафиксированным lockfile.
- Проверка типов и линтер проходят.
- Собираются Vite-приложение и статический Storybook.
- Для каждой позиции перечня есть исходная реализация/композиция и пример.
- Браузерная проверка: адаптивная страница в узком и широком окне, обе темы.
- Проверка ключевых взаимодействий: диалог, меню, выбор даты, форма,
  таблица, уведомление, переключение темы.
- Проверка клавиатурой: Tab, Enter, Escape, возврат фокуса из диалога.
- Доступность: подписи полей, доступные имена и семантика ключевых примеров.
- README содержит точные реально проверенные команды.

## Передача результата

Изменения реализации подготовить в отдельной ветке и pull request, сохранив
возможность просмотра и обсуждения. Спецификация создаёт первый коммит
в пустом репозитории. Саму реализацию не сливать автоматически.

В итоговом сообщении указать ссылку на изменения, команды запуска,
фактическое покрытие каталога и результаты проверок.
Автоматическая публикация сайта и внешняя инфраструктура не входят в этот этап.
