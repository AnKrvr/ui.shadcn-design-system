# Правила работы с дизайн-системой

Этот репозиторий — готовая основа для создания сайтов на React, TypeScript, Vite и Tailwind CSS.

## Перед созданием интерфейса

- Прочитайте README.md и docs/usage.md.
- Проверьте docs/component-inventory.json и src/components/ui: используйте готовые компоненты.
- Посмотрите подходящий пример в src/stories/components и src/components/examples.
- Сохраните провайдеры темы, TooltipProvider и Toaster при замене стартовой страницы.

## Компоненты и композиции

- Импортируйте через @/components/ui, @/components/patterns и @/lib.
- Не переписывайте заново Button, Input, Select, Dialog, Table и другие готовые элементы.
- Собирайте сложные блоки из существующих компонентов.
- Компоненты из одной официальной конфигурации radix-vega. Не заменяйте часть системы другой базой или пресетом.
- Некоторые официальные компоненты этого Radix-пресета сами используют @base-ui/react или @shadcn/react. Сохраняйте их штатные зависимости.
- Общие паттерны помещайте в src/components/patterns, страницы и предметные блоки — отдельно.
- Пропсы и состояния должны соответствовать реальным интерфейсам компонентов.

## Стили и темы

- Используйте bg-background, bg-card, text-foreground, text-muted-foreground, border-border и другие семантические токены.
- Палитра и радиусы задаются в src/styles/globals.css.
- Используйте общую шкалу отступов Tailwind.
- Не добавляйте произвольные hex-цвета, чтобы подогнать одну страницу.
- Проверяйте светлую и тёмную темы, экраны 375 px и широкие экраны.
- Не заменяйте системный шрифт внешним сервисом без явной задачи.

## Доступность и поведение

- Сохраняйте HTML-семантику и связь Label с полем.
- У кнопок с иконками должны быть доступные имена.
- Ошибки связывайте с полями через aria-describedby, не сообщайте о них только цветом.
- Проверяйте Tab, Enter, Escape и возврат фокуса из диалога.
- Показывайте загрузку, ошибки и пустые состояния там, где они возникают.
- Подключайте реальные обработчики; локальные демонстрационные данные явно обозначайте.
- Учитывайте prefers-reduced-motion.

## Проверки

После изменений запускайте проверки по их смыслу:
- npm test — логика темы и проверка перечня;
- npm run typecheck и npm run lint — типы и код;
- npm run build — сайт;
- npm run build-storybook и npm run verify:catalog — каталог;
- npm run test:e2e — пользовательские сценарии и рендеринг примеров.

Не отключайте TypeScript, правила линтера и тесты ради успешной проверки.
Для нового поведения добавляйте проверку пользовательского результата; не тестируйте
реализацию upstream-компонентов повторно без необходимости.

## Сохранение системы

- Не удаляйте каталог Storybook при создании страниц.
- Если меняете исходники общих компонентов, проверьте потребителей и истории.
- При добавлении компонента обновляйте перечень, пример и документацию.
- Сохраняйте лицензии и атрибуцию.
- Применение обновлений upstream — явное изменение: сначала просмотрите diff, затем проверьте сборки.
